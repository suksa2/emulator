## 1. Общее описание

Приложение с графическим интерфейсом (GUI, tkinter) на Python 3,
эмулирующее работу в командной строке UNIX-подобной ОС. Эмулятор работает
с **виртуальной файловой системой (VFS)**, загружаемой из XML-файла.
Все операции выполняются только в памяти: исходный XML-файл никогда не
изменяется.

Возможности:

* окно с областью вывода и строкой ввода; заголовок окна строится из
  реальных данных ОС: `Эмулятор - [username@hostname]`;
* приглашение к вводу `username@hostname:~$` с текущим каталогом VFS,
  ввод и вывод отображаются как диалог, ошибки подсвечиваются,
  история команд листается стрелками ↑/↓;
* простой парсер — ввод разделяется на команду и аргументы по пробелам;
* сообщения об ошибках: неизвестная команда, неверные аргументы и опции;
* параметры командной строки: путь к VFS, путь к лог-файлу и путь к
  стартовому скрипту; отладочный вывод всех параметров при запуске;
* журналирование каждого вызова команды в CSV-файл (дата и время, имя
  пользователя, команда, аргументы, результат);
* стартовый скрипт с комментариями в синтаксисе Python (`#`);
* VFS из XML-файла, двоичные данные в base64, права доступа файлов;
  VFS по умолчанию в памяти, если путь не указан;
* команды: `ls`, `cd`, `whoami`, `uniq`, `uptime`, `chmod`, `cp`,
  `exit` и служебная команда `vfs-info`.

Внешних зависимостей нет — используется только стандартная библиотека
Python 3.8+ (включая tkinter).

## 2. Описание функций и настроек

### 2.1. Параметры командной строки

| Параметр        | Описание |
|-----------------|----------|
| `--vfs PATH`    | путь к XML-файлу VFS; без него создаётся VFS по умолчанию |
| `--log PATH`    | путь к лог-файлу (CSV); без него журнал не ведётся |
| `--script PATH` | путь к стартовому скрипту |
| `--no-gui`      | выполнить стартовый скрипт в консоли без окна (для автоматических тестов) |
| `-h`, `--help`  | справка по параметрам |

При запуске все параметры выводятся в консоль и в окно:

```
[config] Параметры эмулятора:
[config]   log = emulator_log.csv
[config]   no_gui = False
[config]   script = examples/scripts/stage4.txt
[config]   vfs = examples/vfs/deep.xml
```

Коды возврата: `0` — штатное завершение (или код из `exit N`),
`1` — ошибка загрузки VFS, открытия лога или чтения скрипта,
`2` — неверные параметры. Ошибка запуска в режиме GUI дополнительно
показывается в диалоговом окне.

### 2.2. Журнал (CSV)

Каждый вызов команды дописывается в файл, заданный `--log`. Новый файл
начинается со строки заголовка:

| Столбец     | Содержимое |
|-------------|------------|
| `timestamp` | дата и время события, `2026-10-10T21:37:06` |
| `user`      | имя пользователя ОС |
| `command`   | имя команды |
| `args`      | аргументы через пробел |
| `status`    | `ok`, `error` или `exit` |
| `message`   | текст ошибки или код выхода |

```
timestamp,user,command,args,status,message
2026-10-10T21:37:06,student,ls,-l docs,ok,
2026-10-10T21:37:06,student,unknown_command,arg1,error,unknown_command: command not found
```

### 2.3. Стартовый скрипт

Текстовый файл (UTF-8), по одной команде в строке.

* Комментарии — как в Python: от `#` до конца строки (строка целиком
  или окончание строки после команды).
* Перед каждой командой печатается приглашение и сама команда, затем её
  вывод — как при диалоге с пользователем.
* Об ошибке сообщается строкой `[script] error at <файл>:<строка>`,
  выполнение продолжается; в конце выводится число ошибок.
* `exit` завершает эмулятор. После скрипта окно остаётся открытым для
  интерактивной работы.

### 2.4. Формат VFS (XML)

```xml
<vfs name="demo" home="/home/user">
  <dir name="home">
    <dir name="user">
      <file name="hello.txt" mode="600">Hello!</file>
      <file name="logo.bin" encoding="base64">iVBORw0KGgo=</file>
    </dir>
  </dir>
</vfs>
```

| Элемент / атрибут      | Назначение |
|------------------------|------------|
| `<vfs>`                | корневой каталог; обязательный корневой элемент |
| `name`                 | имя VFS (по умолчанию — имя файла) |
| `home`                 | домашний каталог, отображается как `~` (по умолчанию `/`) |
| `<dir name="...">`     | каталог; может содержать `dir` и `file` |
| `<file name="...">`    | файл; текст элемента — содержимое (UTF-8) |
| `encoding="base64"`    | содержимое файла закодировано в base64 |
| `mode="644"`           | права в восьмеричном виде (по умолчанию 755 для каталогов, 644 для файлов) |

Ошибки загрузки: файл не найден, неверный XML, корневой элемент не
`<vfs>`, неизвестный элемент, пустое/недопустимое/повторяющееся имя,
неверный base64, неверный `mode`, отсутствующий домашний каталог.

VFS по умолчанию (без `--vfs`): `/home/user/readme.txt`,
`/etc/hostname`, пустой `/tmp`; домашний каталог `/home/user`.

### 2.5. Команды

Пути могут быть абсолютными (`/etc`), относительными (`projects/app`),
содержать `.`, `..` и `~` (домашний каталог). Короткие опции можно
объединять (`-la`), `--` завершает список опций.

| Команда | Описание |
|---------|----------|
| `ls [-l] [-a] [путь...]` | содержимое каталога (по умолчанию текущего), отсортированное по имени. `-l` — подробный формат (права, размер в байтах или число элементов каталога), `-a` — показывать `.` и `..`. Для нескольких каталогов — заголовки `путь:`. |
| `cd [путь]` | смена текущего каталога. Без аргумента или `~` — домашний каталог, `cd -` — предыдущий. Ошибки: нет пути, не каталог, лишние аргументы. |
| `whoami` | имя пользователя реальной ОС. |
| `uniq [-c] [-d] [-u] [-i] файл` | выводит файл, схлопывая соседние одинаковые строки. `-c` — число повторов, `-d` — только повторяющиеся, `-u` — только уникальные, `-i` — без учёта регистра. |
| `uptime [-p] [-s]` | время работы эмулятора в формате `uptime(1)`. `-p` — `up 1 hour, 5 minutes`, `-s` — время запуска. |
| `chmod [-R] [-v] РЕЖИМ путь...` | смена прав (в памяти). РЕЖИМ — восьмеричный (`640`) или символьный (`u+x`, `go-w`, `a=r`, `u+rw,o-r`, `-x`). `-R` — рекурсивно, `-v` — печатать изменения. |
| `cp [-r\|-R] [-v] ИСТОЧНИК... НАЗНАЧЕНИЕ` | копирование файлов и каталогов (в памяти). Если назначение — каталог, копии помещаются внутрь; при нескольких источниках назначение обязано быть каталогом. Каталоги копируются только с `-r`/`-R`, существующие каталоги объединяются. Копия сохраняет права. Ошибки: нет источника, тот же файл, каталог в самого себя, перезапись файла каталогом и наоборот. |
| `exit [код]` | закрывает окно с кодом возврата (по умолчанию 0). |
| `vfs-info` | служебная: имя VFS, источник, домашний каталог, число каталогов/файлов и объём данных. |

Все сообщения об ошибках начинаются с `error:` и выделяются в окне
красным цветом.

## 3. Сборка, запуск и тесты

Сборка не требуется — нужен только Python 3.8+ с tkinter
(в Linux: пакет `python3-tk`).

Запуск эмулятора:

```bash
./run.sh --vfs examples/vfs/deep.xml --log log.csv
```

```bat
run.bat --vfs examples\vfs\deep.xml --log log.csv
```

```bash
PYTHONPATH=src python3 -m emulator --help
```

Запуск модульных тестов (55 тестов; тесты окна пропускаются, если нет
дисплея):

```bash
python -m unittest discover -s tests -t . -v
```

или `make test`.

Скрипты ОС для тестирования (каталог `scripts/`):

| Скрипт | Что проверяет |
|--------|---------------|
| `test_params.bat` / `.sh` | все параметры командной строки, CSV-лог, отсутствующий скрипт, неверный путь лога, неверный параметр, запуск GUI (этап 2) |
| `test_vfs.bat` / `.sh` | VFS по умолчанию, минимальная, несколько файлов, вложенность 3+ уровня, ошибки загрузки, GUI (этап 3) |
| `test_commands.bat` / `.sh` | стартовые скрипты `stage4.txt` и `stage5.txt`; с аргументом `gui` — в окне (этапы 4–5) |

Стартовые скрипты эмулятора (`examples/scripts/`): `stage2.txt`,
`stage3.txt`, `stage4.txt`, `stage5.txt`.

## 4. Примеры использования

Ниже приведён текст из окна эмулятора (или консоли в режиме
`--no-gui`).

### Этап 1: диалог и ошибки

```
student@pc:~$ ls -l docs
ls: args=['-l', 'docs']
student@pc:~$ foo bar
error: foo: command not found
student@pc:~$ exit abc
error: exit: abc: numeric argument required
```

### Этап 2: стартовый скрипт с комментариями и CSV-лог

```
$ ./run.sh --no-gui --log log.csv --script examples/scripts/stage2.txt
student@pc:~$ unknown_command arg1
error: unknown_command: command not found
[script] error at examples/scripts/stage2.txt:5
...
[script] finished with 2 error(s)
```

### Этап 3: ошибки загрузки VFS

```
$ ./run.sh --no-gui --vfs examples/vfs/broken.xml
error: VFS load failed: invalid XML in 'examples/vfs/broken.xml':
mismatched tag: line 6, column 2
```

### Этап 4: ls, cd, whoami, uniq, uptime

```
student@pc:~$ ls -l
total 2
-rw-r--r--       84 notes.txt
drwxr-xr-x        2 projects
student@pc:~$ cd projects/app
student@pc:~/projects/app$ cd -
/home/user
student@pc:~$ whoami
student
student@pc:~$ uniq -c /var/log/system.log
      2 boot ok
      3 disk warning
      1 network up
student@pc:~$ uptime -p
up 0 minutes
```

### Этап 5: chmod и cp

```
student@pc:~$ chmod -v 0444 /etc/hostname
mode of '/etc/hostname' changed from 0600 to 0444
student@pc:~$ chmod u+x,g-r /etc/motd
student@pc:~$ chmod -Rv 700 projects/app
mode of '/home/user/projects/app' changed from 0755 to 0700
...
student@pc:~$ cp -v notes.txt /tmp
'notes.txt' -> '/tmp/notes.txt'
student@pc:~$ cp projects /tmp
error: cp: -r not specified; omitting directory 'projects'
student@pc:~$ cp -r projects projects/app
error: cp: cannot copy a directory, 'projects', into itself, 'projects/app'
```
